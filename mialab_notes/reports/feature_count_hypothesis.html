More features, better segmentation?

Hypothesis: A larger amount of features improves the segmentation performance.

Not supported

Performance does not rise with the number of features. It jumps once, when five label-prior features add where each structure usually lies, and then stays flat from 12 to 35 features.

Six feature sets with 5 to 35 features, 3 seeds each, 10 test subjects, Dice and 95th-percentile Hausdorff distance (HD95) per structure.

Setup

All experiments use the same pipeline (registration to the atlas, skull stripping, z-score normalization) and the same random forest (50 trees, depth 20, √n features per split). Only the feature set changes. Each experiment ran with seeds 0, 1 and 2, trained on 20 subjects and was tested on the same 10 subjects. Values are means over the 10 test subjects (each first averaged over the 3 seeds), without post-processing. Differences between experiments were tested with a paired Wilcoxon signed-rank test per structure and metric.

What the experiments show

  1. baseline → baseline_t2 · 5 → 7 features

    Adding features without new information does nothing

    The T2 intensity and gradient leave mean Dice unchanged (0.669 → 0.666) and make the hippocampus significantly worse (−0.024 Dice, +1.0 mm HD95, p = 0.002). After normalization T2 is close to a mirror image of T1 (Spearman r ≈ −0.92), so it adds little the forest does not already have.

  2. baseline_t2 → prior_only · 7 → 12 features

    Five label-prior features bring nearly the whole gain

    The label prior gives, for every voxel, the fraction of training subjects that have each structure there. Hippocampus Dice rises by 0.14, amygdala by 0.08, thalamus by 0.04, and HD95 of these three drops from 10–12.5 mm to 3.6–6.8 mm. All 10 subjects improve in every structure (p = 0.002, the smallest possible value with 10 subjects).

  3. prior_only → extended_plus · 12 → 35 features

    23 more features leave Dice unchanged

    Mean Dice is 0.722 for both. Some per-structure differences are statistically significant because they are consistent, but they are about 0.001 Dice, far too small to matter. The one real gain is in HD95 (amygdala 6.8 → 4.0 mm, hippocampus 5.2 → 4.2 mm), and it comes from a specific new kind of feature (distances to the brain border and to the typical structure regions), not from the count. In exchange, test pre-processing takes 7× longer.

  4. extended vs extended_plus · 29 vs 35 features

    More features is not even consistently better

    The 29-feature set has slightly better Dice than the 35-feature set (amygdala +0.017, hippocampus +0.014, p = 0.002), but its hippocampus HD95 is twice as high (8.9 vs 4.2 mm) in every subject and every seed. That points to scattered false-positive voxels far from the hippocampus, which the distance-to-hippocampus feature removes. Adding features traded one metric against the other.

  5. extended_plus → reduced · 35 → 25 features

    Removing 10 redundant features costs almost nothing

    The 10 features removed correlate with a more important one (|r| ≥ 0.9). Dice changes by at most ±0.009 per structure. Only amygdala HD95 gets worse (+1.7 mm), because priordistance_amygdala was among the removed features although it keeps amygdala outliers away.

Why: information, not quantity

The baseline fails where intensity cannot decide. Hippocampus and amygdala have the same MRI intensity as grey matter, so a classifier that only sees intensity and gradient confuses them with the cortex next to them. What it lacks is location, and the label prior and distance features supply it. That is why the gain is large for the three small structures and small (+0.01 Dice) for white and grey matter, which intensity already separates well.

The feature analysis of the 35-feature run points the same way:

  • SHAP ranks distance to the brain border, distance to the typical hippocampus and thalamus regions, T1−T2 and the label priors at the top. All Laplacian-of-Gaussian scales, the coarsest smoothing and the left-right coordinate contribute almost nothing.
  • Correlation: 10 of 35 features are redundant with a more important one (|r| ≥ 0.9). They raise the count without adding information.
  • Boruta confirmed all 35 features, so none is pure noise. A random forest tolerates weak features well (each split picks the best of a random subset), so extra features rarely hurt, which can make "more features helped" look true when only a few did.

Conclusion

Features that add new information improve the segmentation; adding features in itself does not.

The improvement comes from anatomical location (label prior and distance features), mainly for hippocampus, amygdala and thalamus. Beyond about 12 well-chosen features, more features give diminishing returns: the metrics barely move, and the pre-processing time grows several-fold. A reformulated hypothesis for further work: features that encode anatomical location improve the segmentation of subcortical structures more than additional intensity-derived features.

Limitations

  • Only 10 test subjects. With 10 pairs, p = 0.002 means that all 10 subjects changed in the same direction; it says nothing about the size of the effect.
  • The forest settings were fixed for all feature sets and not tuned per set. A set with more features might profit from more trees or a different number of features per split.
  • The feature sets are nested and not random: the feature count and the kind of information change together. The 12-feature set with the prior and the 25-feature reduced set are what separates the two effects.
  • No post-processing was applied. It may remove some of the scattered voxels that drive HD95.
